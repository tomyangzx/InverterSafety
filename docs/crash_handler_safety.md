# Crash Handler Safety Documentation

## Overview
This document describes the crash handler implementation for the 800V inverter system, including safety goals, state transitions, and compliance with ISO 26262 functional safety standards.

## Safety Goals

### SG1: Prevent Unintended Torque During Crash Event (ASIL D)
**Hazard:** Unintended vehicle acceleration or deceleration during a crash event could exacerbate injuries or cause secondary collisions.

**Safety Mechanism:**
- Transition to ASO (All Switches Open) state to disable PWM signals
- Disable gate drivers to prevent any switching activity
- Ensure no torque can be generated by the motor

**Verification:**
- ASO state opens all IGBT/MOSFET switches
- Gate driver power is disabled
- Final state is SAFE_STATE with verified switch status

### SG2: Safely Discharge 800V DC-Link (ASIL D)
**Hazard:** High voltage (800V) DC-link poses electrical shock hazard to first responders and rescue personnel.

**Safety Mechanism:**
- Activate discharge circuit immediately upon crash detection
- Monitor DC-link voltage decay through discharge resistor
- Hold discharge state for configurable time (default 100ms)

**Verification:**
- DC-link voltage reduced by minimum 30% during active discharge
- Final voltage verified to be below safe threshold (≤600V after initial discharge)
- Continuous discharge through resistor until safe level reached

**Note:** In production systems, complete discharge to <60V may take several seconds. The 600V threshold represents the initial safety reduction during the crash sequence.

### SG3: Prevent Back-EMF Overvoltage During High-Speed Shutdown (ASIL C)
**Hazard:** At high motor speeds, suddenly opening all switches can cause the motor to act as a generator, producing back-EMF voltage that exceeds the DC-link rating and potentially destroying components or causing fire.

**Safety Mechanism:**
- Monitor motor speed continuously
- If speed > 3000 RPM, activate ASC (Active Short Circuit) before ASO
- ASC shorts motor windings through bottom switches, creating controlled deceleration
- Hold ASC for configurable time (default 50ms) to safely reduce motor speed

**Verification:**
- ASC activated only when motor speed exceeds threshold
- Motor speed reduced by minimum 50% during ASC phase
- ASC held for sufficient time to prevent back-EMF surge
- Smooth transition from ASC to ASO after speed reduction

## State Machine

### State Transition Sequence

```
NORMAL_OPERATION
       ↓
CRASH_DETECTED (Crash signal received)
       ↓
ACTIVE_DISCHARGE (Enable 800V discharge circuit, 100ms)
       ↓
ASC (Active Short Circuit - only if motor speed > 3000 RPM, 50ms)
       ↓
ASO (All Switches Open)
       ↓
SAFE_STATE (Verify all safety conditions)
```

### State Descriptions

1. **NORMAL_OPERATION**
   - Normal inverter operation
   - PWM control active
   - Monitoring for crash signals

2. **CRASH_DETECTED**
   - Crash signal received from vehicle crash sensors
   - Initiates safety sequence immediately
   - Logs crash event for diagnostics

3. **ACTIVE_DISCHARGE**
   - Activates 800V DC-link discharge relay/MOSFET
   - Current flows through discharge resistor
   - Monitors voltage decay
   - Duration: 100ms (configurable)

4. **ASC (Active Short Circuit)**
   - **Condition:** Motor speed > 3000 RPM
   - All bottom switches turned ON (or all top switches)
   - Creates short circuit path through motor windings
   - Phase currents circulate safely
   - Motor decelerates in controlled manner
   - Duration: 50ms (configurable)
   - **Skipped** if motor speed ≤ 3000 RPM

5. **ASO (All Switches Open)**
   - All PWM signals disabled
   - All IGBT/MOSFET switches open
   - Gate drivers disabled
   - No current flow, no torque generation possible
   - Final electrical isolation

6. **SAFE_STATE**
   - Verifies all safety conditions met:
     - DC-Link voltage ≤ 600V (initial safe level)
     - Motor speed ≤ 3000 RPM (safe for ASO)
     - All switches confirmed open
   - Logs final system state
   - Maintains safe state until manual reset

## ISO 26262 Compliance

### E-Gas Monitoring Concept Integration
This crash handler implements **Level 2: Function Monitoring** safety mechanisms:

- **Independence:** Crash detection and state machine can run on separate core from main FOC control
- **Plausibility Checks:** Motor speed and voltage are continuously monitored
- **Safe State:** ASO provides guaranteed torque-free state
- **Fault Reaction Time:** Complete sequence executes in <200ms

### ASIL Decomposition
- **SG1 (ASIL D):** Decomposed into:
  - ASIL B(D): Crash signal detection
  - ASIL B(D): ASO state execution
  
- **SG2 (ASIL D):** Decomposed into:
  - ASIL B(D): Discharge circuit activation
  - ASIL B(D): Voltage monitoring

- **SG3 (ASIL C):** Single ASIL C requirement (no decomposition needed)

### Freedom from Interference (FFI)
- Crash handler must be protected from interference by QM (non-safety) software
- Memory Protection Unit (MPU) should isolate safety state machine
- Watchdog monitors crash handler execution
- Hardware-enforced state transitions (gate driver disable via hardware signal)

## Configuration Parameters

### Timing Parameters
- `discharge_time_ms`: Duration of active discharge phase (default: 100ms)
  - Range: 50-500ms
  - Longer times provide more voltage reduction
  - Must be balanced with total fault reaction time

- `asc_time_ms`: Duration of ASC phase (default: 50ms)
  - Range: 20-200ms
  - Must be sufficient to reduce motor speed safely
  - Longer times provide more controlled deceleration

### Threshold Parameters
- `high_speed_threshold_rpm`: Motor speed above which ASC is required (default: 3000 RPM)
  - Depends on motor design and back-EMF characteristics
  - Should be calibrated based on motor parameters
  - Lower threshold = more conservative (more ASC activations)

- `safe_voltage_threshold`: Target voltage after initial discharge (default: 600V)
  - Initial safety target during crash sequence
  - Complete discharge to <60V happens over longer time period
  - Allows crash sequence to complete quickly while ensuring reduced hazard

## Usage Example

```python
from crash_handler import CrashHandler, SafetyState

# Initialize crash handler for 800V system
handler = CrashHandler(
    dc_link_voltage=800.0,      # Current DC-link voltage
    motor_speed_rpm=5000.0,     # Current motor speed
    discharge_time_ms=100,      # Active discharge duration
    asc_time_ms=50              # ASC duration
)

# Execute crash sequence (called when crash signal received)
success = handler.execute_crash_sequence()

# Check final state
if success:
    print(f"Crash handled safely. Final state: {handler.get_current_state()}")
else:
    print("Crash sequence encountered errors")
```

## Real-World Implementation Considerations

### Hardware Integration
In a production system, the crash handler would interface with:

1. **Crash Sensors:**
   - Accelerometers (>30g deceleration)
   - Airbag deployment signals
   - CAN bus crash messages

2. **Discharge Circuit:**
   - High-power discharge resistor (e.g., 50Ω, 500W)
   - MOSFET or relay to control discharge path
   - Voltage monitoring (ADC with 12-bit resolution)

3. **Gate Drivers:**
   - PWM disable signals
   - Hardware shutdown pins
   - Fault feedback monitoring

4. **Safety Monitoring:**
   - Independent watchdog timer
   - Redundant voltage/current sensors
   - Program flow monitoring

### Diagnostics and Logging
- Log crash event with timestamp
- Record initial conditions (voltage, speed)
- Log state transitions and timing
- Store fault codes for post-crash analysis
- Enable/disable diagnostics via CAN

### Calibration
Parameters should be calibrated based on:
- Specific motor characteristics (back-EMF constant)
- DC-link capacitance and resistance
- Maximum operating speed
- Thermal limits of discharge resistor
- Regulatory requirements (e.g., <60V in <1s for ISO 6469-3)
